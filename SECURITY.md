# Security reporting

Please do not post credentials, secret values, private infrastructure details,
working exploit payloads against live installations, or sensitive logs in public
issues or pull requests.

Use GitHub private vulnerability reporting if it is enabled for this repository.
If it is unavailable, ask a maintainer for a private reporting channel without
including vulnerability details in the public request. Reproduce issues using
disposable instances and synthetic data only.

The initial release is under development and has not received an independent
security audit. Review [the security model](docs/security-model.md) for trust
boundaries and operational limits. Do not assume that passing CI is security
certification.
